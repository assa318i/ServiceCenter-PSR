# Импорт и экспорт списков

Отдельная инструкция к разделам «Заказчики», «Заявки на ремонт», «Склад» и «Картриджи»:
как перенести в программу чужую выгрузку (1С, Excel, прайс поставщика) и как выгрузить
из программы свой список. Подходит и для первого запуска, когда базу нужно заполнить
сразу целиком, и для обычной сверки, когда из 1С прилетел обновлённый прайс.

Полная документация — `doc.html` (ярлык «Документация целиком» в меню Пуск); здесь только
то, что связано с загрузкой и выгрузкой файлов.

## 1. Форматы файлов

Формат программа определяет по содержанию файла, а не по расширению, поэтому переименованный
`.xls` или файл без расширения не обманет её — она предложит пересохранить правильно.

| Формат | Что принимается |
|---|---|
| `.xlsx` | Excel 2007 и новее, LibreOffice Calc. Из книги берётся лист, чьи заголовки больше всего похожи на нужные колонки; если листов несколько — выбирается подходящий |
| `.csv`, `.txt` | Разделитель (`;`, `,` или табуляция) и кодировка (UTF-8 с BOM, UTF-16, windows-1251) определяются по файлу. Клетки в кавычках со «сдвоенными» кавычками внутри читаются правильно |
| `.xml` | Выгрузка 1С «обмен данными», Excel 2003 XML (SpreadsheetML) и любая таблица из повторяющихся элементов (`<Строка>` / `<item>` с одинаковыми дочерними тегами) |
| HTML-таблица | Страница с `<table>` — например сохранённый из браузера отчёт или письмо с таблицей |
| `.xls` (Excel 97-2003) | **Не читается**: старый бинарный формат. Программа показывает инструкцию: 1С → «Файл → Сохранить как» → «Excel 2007+ (*.xlsx)» или «Выгрузить все данные всех таблиц» → `.xml` / `.csv`; Excel и LibreOffice → «Сохранить как» → `.xlsx` или «Текст CSV (разделители - «;»)» |

Требования к содержанию простые:

* **Первая строка с двумя и более непустыми клетками считается заголовками колонок.** Название
  отчёта одной клеткой выше («Остатки на 01.10.2026») программе не мешает — она его пропускает.
* Пустые строки и строки-«подвалы» из одной клетки («Итого», «Всего», «Строк: 120») читатель
  выбрасывает ещё до импорта. В предпросмотре отдельной строкой «Пустых строк» считаются строки
  файла, в которых пусты все колонки, которыми программа опознаёт запись, — например строка
  прайса без наименования и артикула.
* Колонки можно оставить в любом порядке и назвать своими словами — программа угадает назначение
  по названию, а всё не угаданное правится руками в окне колонок (шаг 3 ниже).
* Лишние колонки не мешают: для каждого своего поля выбирается колонка файла или «— не брать —».
* Числа принимаются в любом привычном виде: `1 234,50`, `1.234,50`, `1,234.50`, `8,5`.
  Пустая клетка и текст вместо числа дают 0, а не ошибку.

## 2. Как устроен импорт: пять шагов

Одинаково во всех четырёх разделах.

1. Кнопка **«Импорт из файла»** на верхней панели нужного раздела.
2. Выбор файла. Если файл не читается, окно говорит почему и показывает, как пересохранить.
3. **Окно «Импорт …: колонки»** — по одному списку на каждое поле справочника. Угаданные
   колонки уже выбраны (программа ищет название колонки по синонимам, регистр, «ё», пробелы
   и знаки не важны). Проверьте и поправьте то, что угадано неверно; ненужное оставьте
   «— не брать —». В заголовке окна видно, сколько в файле колонок и строк.
4. **Предпросмотр**: «Строк в файле: … / Новых …: … / Уже в базе, обновится: … / Пустых
   строк: …» плюс абзац о том, что именно сделают числа из файла. Этот прогон базу **не
   меняет** — он только считает. «Отмена» на этом шаге не оставляет следов.
5. Результат: «Импорт завершён: добавлено …, обновлено …, пустых строк пропущено …».

Гарантии, общие для всех импортов:

* **Одна транзакция.** Если на любой строке что-то пошло не так, откатывается всё и появляется
  «Импорт отменён, база не изменена». Полузагруженной базы не бывает.
* **Пустая клетка файла ничего не затирает.** Файл дополняет и правит карточку только теми
  значениями, которые в нём есть.
* **Повторный импорт того же файла безопасен** — записи ищутся по своим дубль-ключам
  (см. разделы ниже), поэтому файл, загруженный дважды, не удваивает список.
* **Права.** Кнопка у всех одна и та же, но пустить она может только того, кто ведёт раздел;
  остальные получают короткое объяснение, кому этот раздел положен.

## 3. Порядок переноса базы при первом запуске

Порядок, при котором связи между справочниками собираются сами:

1. **Заказчики** — сначала, потому что заявки ищут заказчика в базе.
2. **Склад** (каталог и остатки) — позиции нужны, чтобы расходовать их на заявки.
3. **ЗЧ картриджей** — если ведёте заправку.
4. **Заявки на ремонт** — последние: каждая строка файла привяжется к уже загруженному заказчику.

Перед каждой загрузкой не лишним будет нажать «Резервная копия базы» в «Отчётности» — база
одной транзакцией меняется целиком, и откат к утренней копии всегда доступнее, чем правка
вручную.

## 4. Заказчики

**Где:** раздел «Заказчики» → «Импорт из файла».
**Кто может:** администратор, руководитель сервисных инженеров, бухгалтер, юрист.

| Поле программы | Как чаще всего называется столбец в файле |
|---|---|
| Организация | Организация, Контрагент, Наименование, Компания, Заказчик, Клиент, Партнёр, org |
| ФИО клиента | ФИО, Контактное лицо, Работник, Сотрудник, Name |
| Телефон | Телефон, Тел., Мобильный, phone |
| Адрес | Адрес, Address, Место |
| Контактный телефон | Контакт, Факс, E-mail, Почта |
| Доверенное лицо | Доверенное лицо, Представитель интересов |
| Способ оплаты | Способ оплаты, Оплата, Расчёт, Условия, Payment |
| Примечание | Примечание, Комментарий, Дополнительные сведения, Notes |

Дубль ищется по связке **организация + ФИО** (в нормализованном виде: регистр, «ё» и лишние
пробелы не мешают). Отсюда два практических следствия:

* та же организация с другим ФИО — **новый** заказчик, а не правка старого;
* если в файле организация есть, а ФИО пустое, строка ищется как «организация + пустое ФИО»
  и может создаться отдельной записью — не смешивайте в одном файле карточки компаний
  и карточки физических лиц.

Значения из файла заменяют соответствующие поля карточки; даты оплаты, предоплата, водитель
и финменеджер в этот импорт не входят — их заполняют в карточке.

Строка заголовков CSV, которая грузится без единой правки в окне колонок:

* `Организация;ФИО;Телефон;Адрес;Контактный телефон;Доверенное лицо;Способ оплаты;Примечание`

**Персональные данные.** Импорт заказчиков — это ПДн: ФИО, телефоны, адреса. Держите файл
в папке того отдела, которому они положены, не в общей сетевой папке «на всех» и не в почте;
после переноса проверьте, что инженеру эти поля по-прежнему показаны обезличенно (раздел
«Персональные данные заказчика» в основной документации).

## 5. Заявки на ремонт

**Где:** раздел «Заявки на ремонт» → «Импорт из файла».
**Кто может:** администратор, руководитель сервисных инженеров, инженер, консультант,
сотрудник колл-центра, водитель.

| Поле программы | Синонимы заголовка | Что попадает в базу |
|---|---|---|
| Заказчик (организация или ФИО) | Заказчик, Клиент, Организация, Контрагент, ФИО | Ищется в базе заказчиков по организации, ФИО и их сочетаниям; не нашли — заявка создаётся **без** заказчика, свяжите его в карточке |
| Оборудование | Оборудование, Аппарат, Устройство, Изделие, Модель, Наименование, Товар | Как в файле |
| Серийный/инвентарный № | Серийный, Инвентарный, Заводской, SN | Вместе с датой открытия определяет дубль |
| Неисправность | Неисправность, Проблема, Описание, Дефект, Жалоба | Как в файле |
| Статус | Статус, Стадия, Этап, Status | Русская подпись целиком («В работе», «Завершён, выдан»), английское имя состояния (`IN_WORK`) или кусок русской подписи («в работ», «на столе») |
| Service Level | Service Level, SLA, Уровень, Приоритет | «Обычный»/`normal`, «Внимание»/`warning`, «Опасно»/`critical`; не поняли — уровень остаётся прежний |
| Инженер | Инженер, Мастер, Исполнитель, Engineer | Как в файле |
| Менеджер приёма | Менеджер, Приём, Принял | Как в файле |
| Дата открытия | Открыта, Дата приёма, Поступил, Принят, Регистрац. | `дд.мм.гггг`, `дд/мм/гггг чч:мм`, `гггг-мм-дд`; пусто — текущий момент |
| Ожидание запчасти до | Ожидание, Запчасть, Wait | Тот же формат дат |
| Выдан заказчику | Выдан, Возврат, Issued, Закрыт | Тот же формат дат |
| Цена, руб. | Цена, Стоимость, Сумма, Price, Прайс | Число в любом виде |
| Примечание | Примечание, Комментарий, Notes, Дополнительные | Как в файле |

Особенности, о которых стоит знать заранее:

* **Дубль = серийный № + день открытия.** У строки без серийного номера дубля быть не может,
  поэтому каждая такая строка считается новой заявкой. Если переносите архив заявок без
  серийников, загружайте его один раз — повторный импорт удвоит список.
* Статус, Service Level, даты и цена в существующей заявке правятся только непустыми клетками.
* **Не переносим** комплектность, срок гарантии, отметку о согласовании с заказчиком, фото
  и вложения, дела и переписку в ленте — это появляется только в карточке заявки.
* Каждое движение по заявке попадает в её ленту: «Заявка создана импортом из файла: …» или
  «Данные заявки изменены импортом из файла». Ленту никто не затирает.

Заголовки, которые программа угадывает целиком (это же — выгрузка `remonty.csv`, кроме
колонок «№» и «Гарантия дн.»):

* `Заказчик;Оборудование;Серийный №;Неисправность;Статус;Service Level;Инженер;Менеджер;Открыта;Ожидание до;Выдан;Цена;Примечание`

## 6. Склад: каталог и остатки

**Где:** раздел «Склад» → вкладка «Склад (остатки)» → «Импорт из файла».
**Кто может:** только администратор — импорт меняет весь справочник сразу.

| Поле программы | Синонимы заголовка |
|---|---|
| Артикул | Артикул, Код, SKU, Штрихкод, PartNumber, ItemCode |
| Наименование | Наименование, Название, Товар, Позиция, Описание, Name, Title |
| Группа | Группа, Категория, Подгруппа, Вид, Group |
| Ед. изм. | Ед, Единица, Упаковка, Unit (пусто → «шт») |
| Количество (фактический остаток) | Количество, Остаток, Qty, Кол-во, Число |
| Минимальная норма | Мин, Норма, Min |
| Цена, руб. | Цена, Стоимость, Price, Прайс |

Как считать «Количество»: это **фактическое количество на складе**, а не приход за период.
У новой позиции остаток берётся из файла (база начинается с нуля), у совпавшей позиции он
заменяется, а разница ложится в «Журнал склада» операцией **«Импорт»** со знаком (`+10`
или `-3`). Ведомость с колонкой «приход за месяц» в эту колонку подставлять нельзя — остатки
получатся удвоенными; для движений и так есть журнал.

Дубль ищется по **артикулу**, а если его нет — по **наименованию** (оба сравниваются
в нормализованном виде: регистр, «ё» и лишние пробелы не мешают). Позиции без артикула
опознаются только по названию, так что заводите артикулы: поиск сканером и защита от дублей
работают по ним.

Строка заголовков выгрузки `sklad.csv` грузится обратно без правок:

* `Артикул;Наименование;Группа;Ед.;Остаток;Мин. норма;Цена;Штрихкод`

## 7. ЗЧ картриджей: каталог и два склада

**Где:** раздел «Склад» → вкладка «Картриджи» → «Каталог ЗЧ картриджа» → «Импорт из файла».
**Кто может:** администратор, руководитель сервисных инженеров, заправщик.

| Поле программы | Синонимы заголовка |
|---|---|
| Артикул | Артикул, Код, SKU, Партномер, PartNumber, Штрихкод |
| Название ЗЧ | Название, Наименование, Позиция, Товар, Запчасть, Name |
| Грамовка (тонер на картридж, г) | Грамовка, Грам, Вместимость, Std |
| Тонер на складе, г | Тонер, Порошок |
| Склад заправщика, шт | Склад заправщика, В работе |
| Склад кладовщика, шт | Склад кладовщика, Хранение |
| Мин. норма | Мин, Норма, Min |
| Цена, руб. | Цена, Стоимость, Price, Прайс |

Числа файла — **фактические остатки** двух складов и запас тонера в граммах: у совпавшей
позиции они заменяются. В отличие от склада, **журнал картриджей импорт не пишет** —
операции переноса заправщик потом фиксирует сам, если это нужно для отчётности.

Дубль — по артикулу, иначе по названию.

Строка заголовков выгрузки `kartridzhi.csv`, которая грузится без правок в окне колонок:

* `Артикул;Название ЗЧ;Грамовка, г;Тонер на складе, г;Склад заправщика, шт;Склад кладовщика, шт;Мин. норма;Цена, руб.`

## 8. Экспорт: CSV, XML, резервные копии

Все кнопки в разделе «Отчётность».

| Кнопка | Что получается | Куда кладётся |
|---|---|---|
| **Экспорт CSV (Excel)** | `zakazchiki.csv`, `remonty.csv`, `sklad.csv`, `kartridzhi.csv`, `zhurnal-sklada.csv` | `data\export\` |
| **Выгрузка XML (ЭДО/1С)** | `edo_ГГГГММДД_ЧЧММ.xml`: реквизиты центра, период, заказчики, заявки за период, приходы/расходы, итоги по количеству и сумме | `data\export\` |
| **Резервная копия базы** | Полный файл базы `psr_ГГГГММДД_ЧЧММ.db` и его копии во все папки из «Настройки → Папки для дополнительных копий» | `data\backups\` + указанные папки |
| **Экспорт базы для Android** | Копия базы `psr.db` для мобильной версии (её читают Android-приложения из той же папки) | `data\export\psr.db` |

Про CSV:

* Разделитель — `;`, файл сохранён в UTF-8 с BOM: Excel в Windows открывает его двойным щелчком,
  кириллица не превращается в кракозябры.
* Точку с запятой внутри текста программа меняет на запятую, чтобы строка не разъехалась.
* Все клетки в двойных кавычках.
* Даты — `дд.мм.гггг` (время — через пробел), числа — как их видит Excel.

Про круг «выгрузил → загрузил обратно»:

* `sklad.csv`, `zakazchiki.csv` и `kartridzhi.csv` программа принимает своими же кнопками
  «Импорт из файла» — колонки угадываются по своим названиям, повторная загрузка чистого
  файла не создаёт ни одной новой записи. Это удобный способ проверить выгрузку перед
  передачей в бухгалтерию.
* `remonty.csv` грузится обратно частично. Десять общих колонок — «Открыта», «Статус»,
  «Service Level», «Ожидание до», «Выдан», «Оборудование», «Серийный №», «Неисправность»,
  «Инженер», «Цена» — угадываются по названиям. Колонки «№» и «Гарантия дн.» остаются без
  пары: номер заявки — внутренний ключ базы, гарантию заполняют в карточке. Полей «Заказчик»,
  «Менеджер приёма» и «Примечание» в этой выгрузке нет, поэтому при переносе заявок между
  компьютерами вместе с `remonty.csv` перенесите и `zakazchiki.csv`, заказчики свяжутся сами.
* `zhurnal-sklada.csv` — только для чтения и сверки: журнал складских операций импортом
  не восстанавливают.

## 9. Права: кто что может загружать

| Роль | Заказчики | Заявки | ЗЧ картриджей |
|---|---|---|---|
| Администратор | да | да | да |
| Руководитель сервисных инженеров | да | да | да |
| Бухгалтер | да | нет раздела | нет раздела |
| Юрист | да | просмотр | нет раздела |
| Финансовый директор | просмотр | нет раздела | нет раздела |
| Инженер | нет раздела | да | просмотр |
| Консультант | просмотр | да | нет раздела |
| Сотрудник колл-центра | просмотр | да | нет раздела |
| Водитель | просмотр | да | нет раздела |
| Заправщик | нет раздела | просмотр | да |

«Просмотр» — раздел видно, но кнопка «Импорт из файла» выдаст объяснение, кому он положен,
и ничего не откроет. «Нет раздела» — раздел этой роли не открывается. Право «можно править»
администратор может выдать и лично сотруднику: «Настройки» → «Сотрудники, роли и доступ» →
кнопка «Личный доступ» → для нужного раздела выбрать «можно править». После этого импорт
для этого сотрудника станет доступен (права применяются при следующем входе по PIN).

Импорт **склада** (вкладка «Склад (остатки)») из этого правила исключение: он доступен
только администратору и никак не передаётся ни роли, ни лично сотруднику — импорт меняет
весь справочник и пишет движения в журнал склада.

## 10. Частые проблемы

| Что видно | Что это значит и что делать |
|---|---|
| «Это Excel 97-2003 (.xls) — старый бинарный формат…» | Пересохраните в `.xlsx` или выгрузите `.csv`/`.xml` — способ написан в том же окне |
| «Файл … — закрытый бинарный формат другой программы» | Это не таблица. В исходной программе выберите «Экспорт → CSV/XLSX/XML» |
| «В файле нет таблицы с заголовками» | Первая строка файла должна содержать имена колонок (две и более непустые клетки). Уберите пустые листы и «красивые» шапки из одной клетки |
| «В XML не найдено ни одной таблицы из повторяющихся записей» | В XML нет одинаковых элементов-строк. Проще выгрузить CSV |
| «Укажите колонку организации или ФИО…» и похожее | Ни одно поле, которым программа опознаёт запись, не выбрано. В окне колонок укажите хотя бы его |
| Окно колонок показало «— не брать —» везде | Названия столбцов в файле слишком необычные — выберите колонки руками, импорт всё равно пройдёт |
| «Импорт отменён, база не изменена» | Одна из строк не записалась — текст в том же окне говорит какую и почему. База цела, можно править файл и повторить |
| Новых записей больше, чем ожидали | Дубли не сошлись: у заявок пустые серийные номера, у заказчиков та же организация с другим ФИО, у склада артикул в файле отличается от артикула в базе. Проверьте ключевые колонки и повторите импорт — уже загруженное он не удвоит |
| Остаток склада после импорта «не тот» | В файле в колонке количества был приход за период, а не факт на сегодня. Исправьте файл и загрузите ещё раз или поправьте позицию кнопкой «Изменить», задав поле «Остаток» — правка попадёт в журнал как «Ручная корректировка» |
| Даты уехали на месяц | Файл содержит `мм.дд.гггг` (американский порядок): программа читает первый блок как день. Исправьте формат в Excel на `дд.мм.гггг` |
| Поле заполнилось чужим значением | Заголовки-похожие («Предоплата» и «Способ оплаты», «Ожидание до» и «Выдан») могли притянуть не ту колонку. Проверяйте окно колонок — оно для этого и сделано |

## 11. Если нужен свой формат

Разделы программы расширяемы, и свои импорты тоже: машина импорта лежит в
`src\psr\sc\Importer.java`, а справочники-примеры — в `CustomerImport.java`,
`RepairImport.java`, `WarehouseImport.java`, `CartPartImport.java`. Каждому справочнику
достаточно описать подписи полей, синонимы заголовков и одну функцию записи строки —
диалог колонок, предпросмотр, транзакция и защита от дублей общие. Синонимы заголовков
пишутся строчными и без пробелов: они сличаются с нормализованным заголовком колонки.
Читатель форматов — `Table.java` (CSV, XLSX, XML, Excel 2003 XML, HTML).

Проверки импорта выполняются вместе со всем набором: `build\test\run-all.bat`, секция
`psr.sc.ImportCheck`. Там же проверяется и этот документ: строки заголовков из примеров
ниже должны угадываться целиком, а выгрузки CSV — читаться программой обратно, не создавая
новых записей.
