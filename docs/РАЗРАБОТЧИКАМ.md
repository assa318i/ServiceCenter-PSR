# Разработчикам

Как собрать, запустить, протестировать и не сломать. Пользовательские окна описаны в
[ДОКУМЕНТАЦИЯ.md](ДОКУМЕНТАЦИЯ.md), установка — в [ЗАГРУЗКА-И-УСТАНОВКА.md](ЗАГРУЗКА-И-УСТАНОВКА.md).

## 1. Стек и почему он такой

**Java 8 + Swing + SQLite, одна папка `data\` рядом с программой.** Компьютеры сервисных
центров — это часто Windows 7 64-бит, поэтому весь код компилируется строго
`javac --release 8`: jar должен запускаться и на старой Java 8 из Win7. Никаких
`var`, `List.of`, `Map.of`, text block, `Files.readString`, модулей JPMS.
Никакой серверной части: приложение однопользовательское на своём ПК, «многопользовательность»
— это перенос файла базы и копии, а не общий доступ.

Зависимости лежат в `lib\` и кладутся в classpath руками (никаких Maven/Gradle, чтобы
сборка на чужом ПК не превращалась в поиск репозитория):

| jar | зачем | лицензия |
|---|---|---|
| `sqlite-jdbc.jar` | база | Apache-2.0 |
| `slf4j-api.jar`, `slf4j-nop.jar` | драйверу SQLite нужен логгер, вывод глушим | MIT |
| `javax-mail.jar` + `javax-activation.jar` | автоотправка акта по SMTP | CDDL |
| `zxing-core.jar` | генерация штрихкода Code 128 | Apache-2.0 |
| `lib/dev/zxing-javase.jar` | только для тестов: программное декодирование наклейки | Apache-2.0 |

Шрифт Montserrat (`.ttf` с кириллицей) вшит в jar — `resources\fonts\`, лицензия OFL там же.

## 2. Карта исходников

Всё в одном пакете `psr.sc`, 28 файлов. Ядро:

| файл | что делает |
|---|---|
| `App.java` | окно, нижняя навигация, ярко-красная панель просрочек, трей, «Во весь экран», значок окна из `icon.png` |
| `Db.java` | подключение SQLite, `data\`, схема и миграции |
| `Session.java` | вход по PIN, роль (`ADMIN` / `ENGINEER`), имя сотрудника |
| `Settings.java` | ключ-значение настроек (`name`, `inn`, `address`, `logo`, `mail`, `sla_days`, `cloud_path`, `smtp_*`) |
| `Theme.java` | цвета, шрифты, мятные кнопки (Aero-градиент), заголовки |
| `Plugins.java` | загрузка jar-плагинов из `modules\` |
| `Warn.java` | однострочные предупреждения (красным) |

Окна: `RepairsPanel` + `RepairForm` (заявки), `CustomersPanel` + `CustomerCard`,
`WarehousePanel` (остатки/заказы/рекомендации), `CartridgesPanel`, `KitsPanel`,
`FinancePanel`, `ReportsPanel`, `SettingsPanel`, `Tasks` (дела), `Stream` (лента заявки),
`FilterBar` (фильтр и пресеты), `Alerts` (красная панель и напоминания).

Прочее: `Documents` (квитанция, акт, чек), `Print` (печать и число экземпляров),
`Labels` (этикетки, пакетная печать, толщины штрихкода), `Barcode` (обёртка ZXing),
`Privacy` (обезличивание ФИО/телефонов/адресов и «Очистка ПДн»), `Export` (CSV, XML для
ЭДО/1С, копии базы, SMTP, `backup-dirs.txt`).

## 3. Сборка и запуск

```
build.bat            :: src → build\psr-service-center.jar (классы и шрифты в build\classes)
run.bat              :: старт через javaw из PATH (для разработки)
java -cp "build\psr-service-center.jar;lib\sqlite-jdbc.jar;lib\slf4j-api.jar;lib\slf4j-nop.jar;lib\javax-mail.jar;lib\javax-activation.jar;lib\zxing-core.jar" psr.sc.App
installer\make-installer.bat   :: dist + setup.exe (нужен Inno Setup 6, см. п. 7)
```

Первый запуск на пустом месте просит задать PIN администратора. База создаётся в `data\psr.db`
автоматически — при разработке не пугайтесь, что «появился файл из ниоткуда».

## 4. Данные и миграции

17 таблиц: `settings`, `users`, `customers`, `repairs`, `repair_history`, `attachments`,
`items`, `stock_orders`, `cart_parts`, `cart_ops`, `kits`, `kit_parts`, `payments`, `tasks`,
`chat`, `presets`, `watch`. Всё в `Db.init()`, которая вызывается при каждом `Db.get()`.

* Таблицы — `CREATE TABLE IF NOT EXISTS`.
* Новые колонки — helper `addColumn(st, таблица, колонка)`: в SQLite нет `ADD COLUMN IF NOT
  EXISTS`, на уже обновлённой базе `ALTER` кидает «duplicate column», и исключение
  штатно проглатывается. Так база, перенесённая
  со старого `psr.db`, доживает до новой версии кода без скриптов миграции.
* `repairs.rev` — номер версии заявки: его увеличивают правка карточки, смена статуса,
  SLA и применение набора ЗЧ. Сохранение поверх изменившейся версии не перетирает чужую
  работу, а открывает окно конфликта. Любая новая запись в заявку, которая должна
  конкурировать с другой сменой, обязана трогать `rev` и писать строку в `repair_history`
  (`who`, `kind`).

## 5. Тесты

```
build\test\run-all.bat     :: прогон всех тестов программы
```

Собирает `build\test\classes` и гоняет семь наборов: `FilterE2E`, `PresetE2E`, `TasksE2E`,
`StreamE2E`, `ConflictE2E`, `PagTest`, `FilterTest`. Итог пишется в `build\test\all.out`
(в консоли кириллица искажается, поэтому в файл), в конце — счётчик строк с маркером `FAIL`;
в норме `0`.

Почему в скрипте `%SystemRoot%\System32\find.exe`, а не `find`: в `PATH` лежит GNU `find`
из git, и для него `/c` — начало обхода всего диска `C:` (получается 260 МБ вывода вместо
счё строк). Маркер тоже ASCII (`FAILED`), потому что в файл попадают байты разной кодировки.
`exit /b 0` в конце — чтобы «найдено 0» не считалось падением сборки.

Отдельные утилиты, которые не входят в `run-all.bat`: `PrintSim` и `PrintLabel` (имитация
«мажущего» принтера и проверка, что код читается декодером), `DecodeScan`, `UiShot`,
`PrivacyShot`, `TasksShot`, `StreamShot` (PNG-снимки окон для ручной проверки), `Dbg2`,
`DumpRepairs`. Они пишут `.png` рядом с собой — эти файлы в `.gitignore`.

UI целиком руками не проверяется без принтера и сканера: печать симулируется
`PrintSim`/`PagTest`, штрихкоды декодируются `zxing-javase`.

## 6. Соглашения, нарушение которых стоит времени

**Swing и поток событий.**
* Любое изменение интерфейса — на EDT. Фоновые задачи зовут
  `SwingUtilities.invokeLater`, а `invokeAndWait` только если результат действительно нужен
  сразу и вы уверены, что EDT не стоит в модальном диалоге. Реальный случай из этой базы:
  `FilterBar` в конструкторе панели дёргал `reloadPresets()`, первый `addItem` сам выбирался
  и вызывал `actionPerformed` → `load()` → `Warn.show()` модальным окном на EDT, а внешняя
  сторона в это время ждала в `invokeAndWait`. Симптом — «программа виснет при открытии окна»,
  в jstack — `WaitDispatchSupport`. Лечится флагом `filling` в `FilterBar`.
* Порядок инициализации полей в Swing-панели = порядок исполнения: панель, создаваемая в
  поле, не должна обращаться к полям, объявленным ниже неё.
* Фильтрация и поиск по-русски делаются в Java (`Pattern.CASE_INSENSITIVE | UNICODE_CASE`),
  а не через SQL: `LIKE`/`NOCASE` в SQLite не понимает регистр кириллицы.

**Кодировки и переносы** (их ломают молча):
* исходники и документация — UTF-8;
* `installer\setup.iss` — **UTF-8 с BOM**, без BOM Inno читает его как ANSI и русские надписи
  в помощнике превращаются в нечитаемые значки;
* `*.bat` — только латиница и **CRLF**: `cmd.exe` ломает разбор файла, если по ходу
  выполняется `chcp`, и на чистом LF тоже выдаёт обрывки команд;
* PowerShell 5 на этом компьютере корректно читает скрипты либо ASCII, либо UTF-8 **с BOM**
  (поэтому `launch-test.ps1` получает пути через `$PsscriptRoot`, без кириллицы в тексте).
* `.gitattributes` запрещает конвертацию end-of-line (`* -text`) — не отключать.

**Стиль.** Русский текст интерфейса, английские идентификаторы. Минимальное изменение,
которое решает задачу: без новых абстракций «на будущее», без переименований вокруг правки,
без комментариев о том, *что* делает строка. Комментарий нужен только когда непонятно *почему*
(ограничение Win7, особенности SQLite, обход бага Inno) — такие места в коде уже размечены.
Документацию правят тем же коммитом, что и окно: новая кнопка без строчки в
[ДОКУМЕНТАЦИЯ.md](ДОКУМЕНТАЦИЯ.md) считается незакрычной задачей.

## 7. Свой установщик и свои значки

`installer\setup.iss` — Inno Setup 6; установка в папку пользователя, права администратора
не нужны (программе нужна запись в `data\`). `installer\make-installer.bat` собирает jar,
готовит `build\dist` (jar, `lib\`, `run.bat`, документация в HTML, значки), опционально кладёт
свою Java из второго аргумента и компилирует установщик. Версия в имени файла —
переменная `PSR_VERSION`.

Значок: источник — `installer\icon.jpg`, из него `tools\MakeIcon.java` делает `icon.ico`
(16…256 px, классические BMP-записи — их читают Win7 и Inno) и `icon.png` (нужен, потому что
Java 8 не умеет декодировать `.ico`, а окну программы нужен именно растр):

```
javac --release 8 -encoding UTF-8 -d build\icon tools\MakeIcon.java
java  -cp build\icon MakeIcon installer\icon.ico
```

Что проверялось на Inno Setup 6.7 и без чего сборка молча даёт пустую установку —
в главе 3.1 [ДОКУМЕНТАЦИЯ.md](ДОКУМЕНТАЦИЯ.md): `Types:` у компонента обязателен, условная
сборка — через `#if`, `Exit(True)` не компилируется, `{userprofile}` не существует,
флагов `ischeckable`/`checked` нет.

## 8. Своё окно без пересборки программы

Плагины кладутся в `modules\` рядом с программой. Jar должен содержать класс, реализующий
`psr.sc.PsrPlugin`, и две строки в манифесте:

```
PSR-Plugin: com.example.MoyPanel
PSR-Title: Мой модуль
```

```java
public class MoyPanel implements psr.sc.PsrPlugin {
    @Override public String title() { return "Мой модуль"; }
    @Override public javax.swing.JPanel createPanel() { /* своя панель */ }
}
```

После запуска модуль появляется кнопкой в нижней навигации как отдельное окно. Данные —
те же таблицы SQLite: обращайтесь к `psr.sc.Db.get()` (классы программы видны плагину) или
откройте `data\psr.db` своим JDBC-подключением во **read-only**, если не хотите зависеть от
внутренностей. Сбойный jar не роняет программу: `Plugins` соберёт список и предупредит.

## 9. Чего в репозитории быть не должно

* **`data\` целиком** — там база с персональными данными заказчиков, логотип, сканы
  доверенностей, копии базы и SMTP-пароль в таблице `settings`. Исключён через `.gitignore`;
  проверять перед пушем: `git status --porcelain` не должен показывать ничего из `data/`.
* Артефакты сборки: `build\classes`, `build\dist`, `*.class`, `run.log`, вывод тестов `*.out`,
  снимки `build\test\*.png`.
* Готовый установщик — **лежит исключением** в `release\`: его просят бухгалтерия и
  проверяющие на другом ПК, и это единственный бинарный файл в репозитории. Если версия
  растёт, старый `.exe` из `release\` убирают, чтобы история не раздувалась, — актуальный
  файл всегда на странице Releases.

Открытых вопросов на сейчас: в репозитории нет файла `LICENSE` (пока код публичный без
лицензии, формально «все права сохранены») — выбрать лицензию нужно до того, как репозиторий
начнут использовать снаружи.
