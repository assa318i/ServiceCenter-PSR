# Сервис центр от PSR

Учёт ремонтов, заказчиков и склада для сервисного центра. Десктоп: Java 8 + Swing + SQLite
(Windows 7 64 / 10 / 11). Код в `--release 8`, поэтому jar запускается и на старой Java 8 из Win7.

Готовый установщик лежит в [release/PSR-ServiceCenter-Setup-1.0.1.exe](release/PSR-ServiceCenter-Setup-1.0.1.exe)
и на странице Releases этого репозитория. Персональные данные (`data\` целиком: база, копии,
фото заявок, доверенности, реквизиты и SMTP-пароль) в репозиторий не попадают — см. `.gitignore`.

## Сборка и запуск (ПК)
```
build.bat                        :: компиляция src → build\psr-service-center.jar (нужен JDK, только для сборки)
run.bat                          :: запуск (нужна Java 8+; на Win7 — установить Java 8 x64)
installer\make-installer.bat     :: установщик Inno Setup 6 → build\dist\PSR-ServiceCenter-Setup-<версия>.exe
node tools\md2html.js docs\ДОКУМЕНТАЦИЯ.md build\dist\docs\doc.html   :: документация в HTML
```
Данные: `data\psr.db`, вложения (доверенности/фото) — `data\attaches`, логотип — `data\branding`,
резервные копии — `data\backups`, CSV/экспорт для Android — `data\export`.
Библиотеки в `lib\` (кладутся в classpath): sqlite-jdbc, slf4j-api/nop, javax-mail/activation,
zxing-core (генерация штрихкодов Code 128, Apache-2.0).

## Установщик (проверка на другом компьютере)
`installer\setup.iss` — скрипт **Inno Setup 6** (бесплатный и актуальный; InstallShield для
одно-машинного приложения избыточен, альтернативы — NSIS или WiX, если бухгалтерии нужен MSI
для групповых политик). Установка идёт в папку текущего пользователя и **не требует прав
администратора** — программы нужна запись в `data\` рядом с собой.

Состав сборки: jar, `lib\*.jar`, запускатель `run.bat` (использует свою Java из `jre\`, если она
включена), HTML-документация и чек-лист, значки `icon.ico` (установщик, ярлыки, «Программы и
компоненты») и `icon.png` (окно программы — Java 8 не читает `.ico`). Источник значка —
`installer\icon.jpg`, пересобирается `tools\MakeIcon.java` (глава 3.1 документации). Свою Java
кладёт второй аргумент:
`installer\make-installer.bat "C:\путь\к\jre8"` (для Windows 7 — именно Java 8 x64, сборка из
JDK 17 на Win7 не работает). Версия файла: `set PSR_VERSION=1.1.0`.

Страница «Готово» предлагает флажки: **чек-лист знакомства** (HTML-файл, каждый пункт ссылается
на раздел документации — открывается в браузере по умолчанию), **документация целиком** и
**запустить программу**. Отдельная страница помощника предлагает папки для дополнительных копий
базы (диски, сетевые папки, папки облачных клиентов) — список принимается программой при первом
запуске, если в настройках ещё пусто. Берутся только уже существующие папки: установщик новых
не создаёт. При удалении `data\` остаётся.

Проверка установщика на этом же компьютере (тихо, в `%TEMP%`, без прав администратора):
`build\test\install-test.bat` → `build\test\uninstall-test.bat`. Чтение списка копий
(ANSI/UTF-8/UTF-8 с BOM) проверяет `build\test\seed-test.bat`, все тесты программы —
`build\test\run-all.bat`.

## Копии базы: несколько адресов сразу
Резервная копия пишется в `data\backups` при закрытии, при «Очистке ПДн» и по кнопке в
«Отчётности». В «Настройках» → «Папки для дополнительных копий базы» можно указать **несколько
путей через «;»**: второй диск (`D:\PSR-копии`), флешка, сетевая папка/NAS (`\\server\psr`),
папка облачного клиента, который виден в проводнике (OneDrive, Google Drive, Dropbox, Mail.ru
Облако, Selectel и т.п.). Кнопка «Проверить папки копий» показывает, какие пути доступны; папку
под копии создаёте сами — ни программа, ни установщик новых папок не заводят.
В облако надёжнее складывать копии с датой, а не только живой `psr.db`; общий доступ на несколько
компьютеров через облако не делается — база живёт на одной машине. Подробно — глава 3 документации.

## Вход по PIN и роли
Первый запуск — задание PIN администратора. Сотрудники добавляются в Настройках →
«Сотрудники, роли и доступ»: там же выбирается роль из десяти (администратор, руководитель
сервисных инженеров, финансовый директор, бухгалтер, юрист, инженер, заправщик, консультант,
сотрудник колл-центра, водитель), выдаются личные права сверх роли и блокируется вход на время
отпуска или отгула — до указанной даты включительно.
Роль решает, какие окна видно и можно ли в них править. Персональные данные заказчиков
обезличены для всех, кроме администратора и ролей с доступом к ПДн (руководитель сервисных
инженеров, финансовый директор, бухгалтер, юрист, консультант, сотрудник колл-центра, водитель).

## Окна
- **Заявки на ремонт** — статусы: Открыт ремонт → Согласование ЗЧ/цены → В ожидании запчасти
  (со сроком «Ожидание до») → Запчасть подвезут позже → В работе → На столе у инженера →
  Исполнение → Завершён, выдан.
  Service Level (Обычный/Внимание/Опасно) вручную + авто-красный при просрочке ожидания
  или выхода за целевой срок (задан в настройках). Серийный/инвентарный номер, комплектность,
  гарантия на ремонт (дней) — повторная заявка по той же технике в гарантийный срок помечается
  красным предупреждением. Менеджер приёма (связка приём → согласование → исполнение).
  Печать квитанции о приёме, чек (печатная форма, не фискальный), этикетка со штрихкодом
  Code 128, **пакетная печать наклеек** на незавершённые заявки (размеры 48×30/58×40/90×60 мм,
  N штук на единицу, лист А4 или по одной на страницу для принтера этикеток) и
  **«Найти по штрихкоду»** — сканером по наклейке на технике заявка находится и выделяется,
  применение набора ЗЧ, фото «до/после» к заявке.
- **Дела** (кнопка «Дела» внизу и «Дела по заявке») — задача/звонок/встреча по заявке со сроком
  и ответственным; «Выполнено» закрывает дело и пишет строчку в ленту заявки, а для дела
  с повтором сразу ставит следующее по сроку. Просроченные и сегодняшние дела всплывают
  напоминанием при запуске (при заполненном SMTP — письмом) и в красной панели.
- **Лента заявки** (кнопка «Лента заявки») — вся заявка одним хронологическим списком: *реплики*
  сотрудников, *пометки для своих* и *изменения полей* (статус, SLA, фото, набор ЗЧ, дела) с автором
  каждой записи. Фильтр «Всё / Реплики / Изменения / Пометки», реплика с `@Имя` попадает в общий чат,
  а подписка «Слежу за заявкой» при запуске показывает, что появилось нового (таблица `watch`).
- **Конфликт сохранения** — у заявки есть номер версии (`repairs.rev`, его меняют правка
  карточки, статус, SLA и набор ЗЧ). Если заявку успел изменить другой сотрудник, сохранение
  не перетирает его работу молча: окно «Показать отличия / Записать мою версию / Оставить
  версию базы». «Показать отличия» перечисляет разошедшиеся поля (`Цена: в базе «1500» ·
  у меня «2200»`) и оставляет карточку открытой; перезапись и отмена правки фиксируются
  в ленте заявки.
- **Персональные данные** — инженер видит справочник заказчиков обезличенно (ФИО `И***`,
  телефон `*** **67`, адрес `г. Тула ***`), но фильтр ищет по настоящим данным, а полная
  карточка открывается только администратору. Кнопка «Очистка ПДн» по заявлению субъекта
  делает резервную копию базы, стирает данные карточки и удаляет её сканы с диска; заявки,
  оплаты и долги остаются, отчётность не страдает.
- Над окнами — ярко-красная панель просрочек (SLA, запчасти, заказы, нормы склада).
- **Фильтр** — строка под шапкой в окнах «Заявки», «Заказчики» и «Склад (остатки)»: текст
  (слово = подстрока, `*` = маска, несколько слов через пробел = «и»), флаги «назначено мне»,
  «просроченные», «ниже минимума» и сохранённые пресеты (таблица `presets`). Работает по-русски
  без учёта регистра: фильтрует Java, а не SQL — LIKE/NOCASE в SQLite не понимают кириллицу.
- **Заказчики** — сортировка по организации / ФИО / телефону / адресу, поиск.
  Двойной клик — карточка крупным шрифтом: все данные, контакты (тел., лицо с доверенностью,
  водитель, финменеджер), способ/дата оплаты, предоплата и дата её получения.
  Вложения PDF/JPG (доверенности на получение/выдачу). Печать акта о выполненных работах:
  разбивка по страницам на границах абзацев и выбор числа экземпляров (1–5, по умолчанию 3).
- **Склад** — 6 вкладок: остатки (артикул, группа, штрихкод, минимальная норма — её задаёт
  администратор; «Найти по штрихкоду» сканером и «Этикетка позиции»),
  заказы на склад (статусы Новый/Принято — при принятии остаток растёт),
  рекомендации по пополнению (позиции ниже нормы, «Заказать всё по рекомендациям»),
  **Журнал склада** (каждое движение: операция, количество со знаком, заявка, кто внёс),
  **Картриджи** (каталог ЗЧ с граммовкой, два склада — заправщик/кладовщик с перемещениями,
  списание тонера по граммам с привязкой к заявке, внутренний чат с автообновлением),
  **Наборы ЗЧ** (каталоги наборов запчастей с привязкой к единице техники; «Набор ЗЧ к заявке»
  списывает совпавшее с каталогом и создаёт заказ на нехватку). Остаток меняется только из
  операции — цифра в таблице и журнал объясняют друг друга. Каталог и остатки загружаются из
  чужого файла (`.xlsx`, `.csv`, `.txt`, `.xml`, HTML): колонки выбирает человек, дубль ищется
  по артикулу, загрузка идёт одной транзакцией (только администратор). На заявку запчасть
  списывается кнопкой «ЗЧ на заявку» в окне «Заявки».
- **Бухгалтерия** (администратор) — приходы/расходы по period-фильтру: дата, направление,
  заказчик, сумма, способ, привязка к заявке; итоги прихода/расхода/сальдо.
- **Отчётность** — за неделю/месяц/квартал/год: ремонты по статусам, SLA, склад, заказчики.
  Печать с выбором числа экземпляров; акт взаиморасчётов — печать, отправка в почтовое приложение (mailto) или автоотправка
  SMTP прямо из программы (сервер/порт/логин/пароль в Настройках, есть «Тест SMTP»);
  экспорт CSV (Excel) заказчиков/ремонтов/склада и журнала склада; **выгрузка XML (ЭДО/1С)** за период —
  реквизиты, заказчики, ремонты, оплаты, итоги; резервная копия базы (и при закрытии окна);
  копирование базы в папку CloudDisk/сервера из настроек; экспорт `data\export\psr.db` для Android.
- **Настройки** — название центра, логотип (показывается слева вверху в каждом окне), ИНН,
  адрес, почта для отчётов, целевой срок ремонта в днях.

**Свои модули/API**: jar-плагины из папки `modules` (интерфейс `PsrPlugin`, манифест
`PSR-Plugin`/`PSR-Title`) добавляются кнопками в навигацию без пересборки программы.

Цвета: серый фон; важный и опасный текст — красный/ярко-красный; обычный — чёрный.
Кнопки — скруглённые, мятный градиент в стиле Windows 7 Aero (наведение/нажатие подсвечиваются).
Шрифт Montserrat (встроен в jar, кириллица есть).

В окне — кнопки **«Во весь экран»** (развернуть/восстановить) и **«В трей»**: программа прячется
в системный трей, клик по значку (или меню «Открыть окно») возвращает окно, «Выход» из меню
трея делает резервную копию и завершает работу.
